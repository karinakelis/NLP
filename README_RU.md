# Ties — извлечение отношений между персонажами (без LLM)

Система читает рассказ и находит персонажей, связи между ними, тип и тон отношений, а также то, как тон меняется по главам. Используются только spaCy, VADER и наши правила.

## Как запустить (Windows)

Сначала откройте **внутреннюю** папку `ties_week1`, где лежит `ties.py`.
```
py -m pip install -r requirements.txt
py -m spacy download en_core_web_sm
py ties.py sample_story.txt                     # результат + graph.png + relations.csv
py evaluate.py holdout_story.txt gold_holdout.csv   # точность
py -m streamlit run app.py                      # веб-интерфейс
```
Если на Python 3.14 spaCy не устанавливается, поставьте Python 3.12 и пишите `py -3.12 -m ...`.

## Как работает `ties.py`

### Шаг 1. Главы — `split_chapters`
Режет текст по строкам `Chapter 1` / `Chapter One`. Если текст скачан с Project Gutenberg, служебная шапка и концовка (`*** START OF ...`) удаляются.

### Шаг 2. Персонажи — `find_aliases`, `name_of`
- **spaCy NER** находит имена (метка `PERSON`); титулы Mr., Mrs., Dr. убираются.
- Короткое имя приклеивается к полному: «Anna» → «Anna Petrova». Фамилия становится псевдонимом, только если она уникальна: у Clara Hale и Oliver Hale она общая.
- Второй проход: известные имена ищутся по всем словам, потому что spaCy иногда считает «Daniel» организацией.
- Персонаж должен встретиться **минимум 2 раза**.
- **Чистка ошибок spaCy:** «A Mrs Smith» → «Smith», «Mr Elliot, Anne» → два разных человека, «I», «God», «Sir» не считаются персонажами.
- **Места отсеиваются:** если имя часто стоит после «in / at / near» («in Bath») или перед «Hall / Street / Place» («Kellynch Hall»), это место, а не человек.
- **«Mrs Smith» ≠ «Charles Smith»:** фамилия после женского титула не приклеивается к мужскому полному имени.

### Шаг 3. Пол — `guess_genders`
Пол нужен, чтобы понять, к кому относятся he/she. Источники:
- **список имён** NLTK (~8000 мужских и женских имён, папка `data/names`): Charles — мужское, Anne — женское. Это самый сильный источник;
- титул: Mrs. → женский, Mr. → мужской;
- роль: «her **son** Oliver» → Oliver мужчина;
- контекст: «Clara denied it. **She** went home» → Clara женщина;
- по ходу текста: если «She smiled» связали с Rosa, Rosa запоминается как женщина.

### Шаг 4. Упоминания: имена + местоимения + роли — `resolve_mentions`
- **Местоимение** → самый недавний персонаж того же пола (в этом или предыдущем предложении).
- **Правило дополнения:** в «Victor shouted at **him**» him ≠ Victor, потому что дополнение не может быть подлежащим того же глагола.
- **Явные роли:** «her son Oliver», «Lucy, the daughter of Victor», «Peter's cousin Nora» сохраняются. Позже «her son» понимается как Oliver.

### Шаг 5. Прямые действия — `interactions`
Разбор предложения spaCy даёт **кто → что сделал → кому**:
- «Reed threatened James» → (Reed, threaten, James);
- «Anna and Mark talked» → Anna и Mark вместе;
- «Mia asked Peter to help her» → помогает Peter (дополнение главного глагола);
- **Отрицание:** «did **not** trust» не считается дружбой.
- Слова после предлогов места («**at** the wedding», «**about** Rosa») не влияют на тип. Поэтому «James stood beside Oliver at the wedding» не делает их парой.

### Шаг 6. Тип отношений — `relation_type`
Очки по категориям **family, romance, friendship, work, conflict**:

| Источник | Очки |
|---|---|
| Явная роль («her son Oliver») | +5 |
| Слово из списка в прямом действии этой пары | +2 |
| Слово из списка в предложении, где только эти двое | +1 |

Правила выбора:
1. **Явная роль решает сразу:** «her son Oliver», «the daughter of Victor» или **общая фамилия** (Anne Elliot и Walter Elliot) → семья.
2. Иначе побеждает категория с наибольшим числом очков. **Романтика ×2**: такие слова редкие, но значат много.
3. **Конфликт** побеждает, только если у него строго больше очков: начальник может ругать сотрудника, но они всё равно коллеги.
4. Если персонажи общаются, но слов-признаков нет → **acquaintance** (знакомые). Раньше это было «unknown».

Слова родства (brother, sister…) **не** считаются словами-признаками: в «He talked to Anne about his sister» речь о третьем человеке. Родство берётся только из явных ролей и фамилий.

Слова сравниваются в нескольких формах (лемма, само слово, слово без -ed/-ing/-s), потому что spaCy иногда ошибается: «hated» → «hat».

### Шаг 7. Тон
Для каждого общего предложения: **50% VADER + 50% глаголы** (hug, thank, kiss: +1; threaten, accuse, mock: −1; «laughed **at**» = насмешка). Среднее ≥ 0.25 → positive, ≤ −0.25 → negative, иначе neutral.

### Шаг 8. Развитие по главам + фильтр шума
- Тон считается отдельно по главам: `Ch1:positive → Ch2:negative → Ch4:positive`.
- **Фильтр шума:** пара показывается, только если есть прямое действие или явная роль, **или** персонажи вместе хотя бы в 2 предложениях. Так отсекается «Oliver told James about Rosa» → James–Rosa.

### Шаг 9. Описание и граф
Описание собирается по шаблону. Граф строит **networkx** и рисует **matplotlib**:
- **цвет линии = тип отношений** (легенда под графом), толщина = как часто вместе, **пунктир = негативный тон**, размер узла = насколько персонаж связан с другими;
- раскладка **Kamada-Kawai** — узлы распределяются равномерно и не слипаются;
- в книге десятки персонажей, поэтому показываются только **15 главных** и у каждого **3 самые сильные связи**. На сайте оба числа меняются ползунками.

## Результаты

| Рассказ | Версия | F1 (пары) | Тип | Тон |
|---|---|---|---|---|
| sample (на нём писали) | старая | 0.93 | 1.00 | 0.33 |
| | **новая** | **1.00** | **1.00** | **1.00** |
| test (на нём искали ошибки) | старая | 0.92 | 0.83 | 0.40 |
| | **новая** | **1.00** | **1.00** | **1.00** |
| **holdout (контрольный)** | старая | 0.93 | 0.57 | 0.33 |
| | **новая** | **1.00** | **0.50** | **0.75** |

**Обновление:** после расширения словарей контрольный рассказ даёт тип 0.75 и тон 1.00, но он уже **не чистый тест**: часть добавленных слов (envy, confront, pay) взята из его ошибок.

**Проверка на настоящих книгах** (Jane Austen «Persuasion», 83 тыс. слов, около 2 с; Lewis Carroll «Alice»): главные пары определяются правдоподобно. Anne–Wentworth = romance, Anne–Elizabeth/Walter Elliot = family, Wentworth–Harville = friendship. Ошибки остаются: Anne–Lady Russell = romance (на самом деле крёстная и подруга). Для отчёта стоит разметить 15–20 главных пар Persuasion и посчитать точность.

**Честный вывод для защиты:** на рассказах, где правила настраивались, всё 100%. На **новом** тексте пары и тон стали заметно лучше, а **тип отношений остаётся слабым местом (50%)**. Причина — маленькие списки слов: «envied», «confronted», «liar», «paid», «deliver» в них нет, и пара получает «unknown». Это ограничение подхода на правилах, и его нужно показать на слайде Risks.

## Что делать дальше (по порядку)

1. **Расширить списки слов** в `KEYWORDS` и `POSITIVE_VERBS`/`NEGATIVE_VERBS` (envy, confront, liar, rumour, pay, deliver, dislike, engaged…). Удобно брать синонимы из WordNet (`nltk`).
2. **Тип по последним главам.** Mia–Nora: сначала конфликт, потом подруги, а система выбирает тип по всей книге. Можно давать больше веса последним главам.

## Один персонаж под разными именами
Пример: в «Графе Монте-Кристо» Эдмон Дантес = граф Монте-Кристо = аббат Бузони. Что программа делает сама:
- **Титулы** (M., Monsieur, Madame, Mademoiselle, Abbé, Count, Baron, Signor…) убираются из имени;
- **«Dantès» → «Edmond Dantès»:** короткое имя относится к варианту, который встречается в 3+ раза чаще остальных (а не к отцу, Louis Dantès);
- **«the count» → Monte Cristo:** титул без имени относится к персонажу, которого чаще всего так называют («Count of Monte Cristo»). Так же работает «the captain», «the admiral».

**Тайную личность правила знать не могут: это сюжет.** Поэтому на сайте есть поле **«Same person»**: `Edmond Dantès = Monte Cristo = Busoni`. В коде — `analyze(text, same_people="A = B; C = D")`. После объединения главный герой Монте-Кристо получает ~3600 упоминаний и оказывается в центре графа.

**Что ещё ошибается на этой книге:** «Villefort wants to **marry** Valentine to Franz» (выдать замуж) считается романтикой между отцом и дочерью; Danglars склеивается с Madame Danglars. Это ограничения правил на словах.

## Ограничения (для слайда Risks)
- Местоимения: только he/she; «they» и «I» (рассказ от первого лица) не обрабатываются.
- Маленькие списки слов → тип «unknown» на новых текстах.
- Пол определяется эвристически и может ошибаться, если персонаж почти не упоминается.
- Модель `en_core_web_sm` маленькая; `en_core_web_lg` точнее, но тяжелее.
